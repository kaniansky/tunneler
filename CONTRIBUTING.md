# Contributing

## Setup

```bash
npm install
npm run watch   # builds src/ -> public/, rebuilds on change, runs server.js under --watch
```

Open `http://localhost:8042/`, name a session, open Blue/Green links in separate tabs to exercise the
multiplayer path (see CLAUDE.md's "Run / build / deploy" section for full detail).

## Before opening a PR

- `npm run build` must succeed (also runs in CI).
- There's no test suite or linter yet — verify changes by hand: hit the relevant role's URL(s) in a
  browser (blue/green/spectate need two peers; `/play` and `/ai/<easy|medium|hard>` are single-browser).
- Keep `src/` as the only place client-facing files are edited — `public/` is generated by `build.js` and
  gets wiped on the next build.
- Don't hand-edit anything under `public/`.

## Releasing

Tag a commit on `main` with `vX.Y.Z` and push the tag. That triggers:

- `docker-publish.yml` — builds and pushes `ghcr.io/<owner>/<repo>:X.Y.Z` (+ `latest`, `X.Y`, short-sha).
- `release.yml` — creates a GitHub Release with auto-generated changelog notes.

## Code style

See `CLAUDE.md` at the repo root for the project's architecture and conventions before making non-trivial
changes (roles, WASM boundary, wire protocol, etc.) — it documents a number of non-obvious constraints
(route registration order, absolute asset paths, role-gated key input) that are easy to accidentally break.
