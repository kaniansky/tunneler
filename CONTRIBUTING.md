# Contributing

## Setup

Node.js 20.19 or newer (the code is ES modules; node requires them as they are).

```bash
npm install
npm run watch   # builds src/ -> public/, rebuilds on change, runs server.js under node --watch
```

Open `http://localhost:8050/`. For online play open the lobby in two browsers (or a normal and a private
window), create a game, join as BLUE in one and GREEN in the other, and add a third tab as spectator.

## Before opening a PR

- `npm run build` and `npm test` must pass (both run in CI).
- `npm test` covers: every language fits its boxes (`test/lang-check.js`), the engine matches the original
  DOS game frame by frame (`test/compare-wasm.js`), the computer player (`test/ai-sim.js`), online play
  with real sockets (`test/net-sim.js`), the screens in a stub DOM (`test/net-page-smoke.js`, `test/local-check.js`)
  and the app's routes leaving nothing behind (`test/app-check.js`).
- Phone layout changes: also run `npm run check:phone` (a real Chromium: `npm i --no-save playwright-core`;
  not in CI) - the game screen with the touch controls upright and sideways, the end of a match.
- Edit files in `src/` only - `public/` is generated by `build.js` and wiped on every build. A new language or
  game mode also needs its line in `src/lang/index.js` / `src/js/modes/index.js` (the tests check).
- Changing game behaviour in `src/js/engine.js`? It is a faithful port of the decompiled original; keep it
  that way and keep `test/compare-wasm.js` green.

## Releasing

A release is made by pushing a version tag; pushes to `main` only run CI.

1. Set the version (`npm version 1.4.1 --no-git-tag-version` sets `package.json` / `package-lock.json`
   and adds the release to the Flatpak's metainfo - by hand: `node tools/flatpak-update.js --metainfo 1.4.1`;
   the tests fail while it's missing) and rename CHANGELOG.md's "## Unreleased" section to it (e.g. `## 1.4.1`).
2. Commit, push `main`, wait for CI, then tag and push the tag:
   `git tag -a v1.4.1 -m v1.4.1 && git push origin v1.4.1`.

The tag runs `.github/workflows/release.yml`:

- a GitHub Release whose notes are that version's CHANGELOG.md section (`tools/changelog-notes.sh`);
- the desktop app for Windows, Linux and macOS attached to it (`app-build.yml`);
- the Docker image (linux/amd64 + arm64) pushed to `ghcr.io/<owner>/tunneler-online` as `latest`,
  `X.Y.Z`, `X.Y` and the short commit sha;
- the homepage (`site/`) uploaded to https://kaniansky.com/tunneler/;
- the Flatpak manifest (`flatpak/`) updated for it - both `.deb` sha256, the tag and its commit - and
  committed to `main` (job `flatpak`). On Flathub, its bot then opens the update by itself (the manifest's
  `x-checker-data`).

`release-notes.yml` (Actions tab -> Run workflow) rewrites an existing release's notes from the
changelog; `docker-publish.yml` builds an image by hand.
