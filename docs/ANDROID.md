# The Android app

The desktop app (`src-tauri/`, Tauri v2) built for Android with Tauri's mobile support: the same
`public/` pages in the system WebView (served as `http://tauri.localhost/`, so `Endpoint.isApp` is
true and online play goes to the server from the Settings screen, by default
https://tunneler-online.onrender.com).

- Application id: `com.kaniansky.Tunneler`, the same as the desktop app's and the Flatpak's (`tauri.conf.json`
  `identifier`; until 6.0.1 `com.kaniansky.TunnelerOnline` here and `io.github.kaniansky.tunneler-online` on the
  desktop). `src-tauri/tauri.android.conf.json` only adds the Android settings.
- Version: `package.json`'s; versionCode = major * 1000000 + minor * 1000 + patch (5.0.0 -> 5000000),
  computed by the Tauri CLI. Every Google Play upload needs a higher versionCode, i.e. a new version.
- Android 7.0 (API 24) or newer; ABIs arm64-v8a, armeabi-v7a, x86_64 (one universal APK / AAB; no 32-bit x86 since 5.0.4).

## Where things are

| | |
|---|---|
| `src-tauri/src/lib.rs` | the whole app (`run()`, the commands). `main.rs` only calls `run()` on the desktop; Android loads `libtunneler_lib.so` and calls it through `tauri::mobile_entry_point` |
| `src-tauri/Cargo.toml` | `[lib]` `tunneler_lib`, crate types staticlib / cdylib / rlib; the updater and opener plugins are desktop-only dependencies |
| `src-tauri/tauri.android.conf.json` | merged over `tauri.conf.json` for Android: the identifier, minSdkVersion |
| `src-tauri/gen/android/` | the Android Studio / Gradle project (generated by `tauri android init`, then edited - see below; committed). Build output, `jniLibs`, `assets`, the `generated/` Kotlin and `keystore.properties` are gitignored |

What differs from the desktop app:

- **No updater.** Google Play / the APK channel updates the app. `update_check` answers "no update";
  `update_install` / `update_page` answer an error (home.js shows no update item either way).
- **Always fullscreen** (`MainActivity.kt`): immersive mode - status and navigation bars hidden, a swipe
  from the edge shows them for a moment. `set_fullscreen` / `is_fullscreen` answer an error; screen.js
  then changes nothing.
- **The screen stays on** while the app is in front (`FLAG_KEEP_SCREEN_ON`; also on the menus).
- **Back** (button or gesture) is the game's Esc key - "Esc goes back everywhere" - sent with its scan
  code so `KeyboardEvent.code` is "Escape". On the main menu Back closes the app (moves it to the
  background) when the page defines `window.tunnelerBackExits()` returning true there; without that
  function Back is always Esc (it never closes the app; Home does).
- **Plain http allowed** (`usesCleartextTraffic` true in release too): the Settings screen's Server may be
  a server on the local network (`192.168.1.5:8050` -> `http://...`). The public server is https / wss.
- `INTERNET` is the only permission. Portrait and landscape both work (the touch controls lay out for
  each); rotating doesn't restart the page (`configChanges`). Black window background (no white flash).
- Icon: an adaptive icon - `ic_launcher_foreground` (the tank inside the 66 % safe zone, the ground across the
  whole width) on `#D48A3F` (`res/values/ic_launcher_background.xml`), plus `ic_launcher` / `ic_launcher_round`;
  all from `node tools/make-icons.js`.

## Tools

- Node.js >= 20.19 (e.g. 24), the repository's `npm ci`.
- Rust (stable) with the Android targets:
  `rustup target add aarch64-linux-android armv7-linux-androideabi x86_64-linux-android`
- JDK 17 or newer (21 works) - `JAVA_HOME`.
- Android SDK (`ANDROID_HOME`, e.g. `~/Android/Sdk`) with the command-line tools and the NDK
  27.2.12479018 (`sdkmanager --install "ndk;27.2.12479018"`; `NDK_HOME=$ANDROID_HOME/ndk/27.2.12479018`).
  Gradle downloads the platform (android-37) and build tools it needs into the SDK by itself.

```sh
export ANDROID_HOME=$HOME/Android/Sdk
export NDK_HOME=$ANDROID_HOME/ndk/27.2.12479018
export JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64
```

## Build

From the repository root, after building the pages (`node build.js` - the app embeds `public/`):

```sh
node build.js
# a debug APK for a phone (arm64) and the emulator (x86_64); ~250 MB: unstripped debug libraries
npx @tauri-apps/cli@2 android build --debug --apk --target aarch64 --target x86_64
#   -> src-tauri/gen/android/app/build/outputs/apk/universal/debug/app-universal-debug.apk
# release, all ABIs (~7 MB per ABI): APK to install directly, AAB for Google Play
npx @tauri-apps/cli@2 android build --apk --aab
#   -> .../outputs/apk/universal/release/app-universal-release.apk (app-universal-release-unsigned.apk without a key)
#   -> .../outputs/bundle/universalRelease/app-universal-release.aab
```

Gradle runs the Tauri CLI itself (`buildSrc/.../BuildTask.kt`) through `npx --yes @tauri-apps/cli@2`
(package.json has no `tauri` script).

Install and look at it:

```sh
adb install -r src-tauri/gen/android/app/build/outputs/apk/universal/debug/app-universal-debug.apk
adb logcat | grep -i -e RustStdoutStderr -e chromium -e Tauri
```

A debug build's WebView can be inspected from desktop Chrome at `chrome://inspect`.

## Signing

An APK installs only when signed; Google Play wants the AAB signed with an **upload key** (with Play
App Signing, Google holds the real app signing key). Make the upload keystore once and keep it (and its
passwords) safe - every later update must be signed with the same key:

```sh
keytool -genkeypair -v -keystore ~/.tauri/android-upload.jks -storetype JKS \
  -keyalg RSA -keysize 2048 -validity 10000 -alias upload
```

Local release builds sign when `src-tauri/gen/android/keystore.properties` exists (gitignored, never
commit it):

```properties
storeFile=/home/<you>/.tauri/android-upload.jks
storePassword=...
keyAlias=upload
keyPassword=...
```

(`storeFile` absolute or relative to `src-tauri/gen/android`.) Without the file the release APK / AAB
stay unsigned.

## Releases (CI)

`.github/workflows/app-build.yml`, job `android` (release.yml calls the workflow for every `vX.Y.Z`
tag; a push to an `app/**` branch or a manual run builds workflow artifacts only): Java 21, NDK
27.2.12479018, the four Rust targets, `tauri android build --apk --aab`, and attaches to the release

- `tunneler-<v>-android.apk` and `tunneler-<v>-android.aab` - signed, with the repository
  secrets
  - `ANDROID_KEYSTORE` - the keystore file as base64 (`base64 -w0 ~/.tauri/android-upload.jks | gh secret set ANDROID_KEYSTORE` - the file must exist: a wrong path sets an empty secret, and the release comes out unsigned)
  - `ANDROID_KEYSTORE_PASSWORD`
  - `ANDROID_KEY_ALIAS` (e.g. `upload`)
  - `ANDROID_KEY_PASSWORD` (optional; the keystore password when missing)
- or, without `ANDROID_KEYSTORE`, `...-android-unsigned.apk` / `.aab` (an unsigned APK doesn't install).

The run's artifact `android-symbols` (not attached to the release) holds
`tunneler-<v>-android-native-debug-symbols.zip`: the unstripped Rust libraries for Play Console (the packed ones are
stripped by `app/build.gradle.kts` `stripRustRelease`; docs/play-store/README.md, Native debug symbols).

The desktop updater's latest.json (updater-manifest.yml) only lists `.sig` files, so the Android files
don't touch it.

## Google Play

1. A Google Play developer account (one-time fee; identity verification; a new personal account must
   run a closed test with testers for some days before it can publish to production).
2. Create the app, package name `com.kaniansky.Tunneler` (fixed forever once uploaded).
3. Play App Signing on (the default); upload the signed `.aab` from a release.
4. Store listing (texts, the 512 x 512 icon - `docs/play-store/icon-512.png` -, a 1024 x 500 feature
   graphic, phone screenshots), content rating questionnaire, target audience, the Data safety form
   (online play sends the chosen player name and chat to the game server; nothing else is collected),
   and a privacy policy URL (e.g. a page on kaniansky.com/tunneler).
5. Each release: tag -> CI -> upload the new `.aab` (a higher versionCode = a newer version). Google
   Play requires a recent target SDK every year (the generated project targets API 37).

The APK can also be offered directly (GitHub release, the homepage): users allow "install unknown
apps" for their browser. F-Droid builds from source itself and would need its own recipe (the Rust +
NDK build, no prebuilt binaries) - not set up.

## If `tauri android init` is run again

It rewrites `src-tauri/gen/android/` from the template. Then put back:

- `app/src/main/java/com/kaniansky/Tunneler/MainActivity.kt` (immersive, keep screen on, Back = Esc)
- `buildSrc/src/main/java/com/kaniansky/Tunneler/kotlin/BuildTask.kt`: executable `npx`, arguments
  `--yes @tauri-apps/cli@2 android android-studio-script` (the template runs `npm run -- tauri`)
- `app/build.gradle.kts`: the `keystoreProperties` signing block, release `signingConfig`, and
  `usesCleartextTraffic` "true" in `defaultConfig`
- `res/values/themes.xml`, `res/values-night/themes.xml`: `android:windowBackground` black
- the icons: `node tools/make-icons.js` writes the `mipmap-*` icons and `res/values/ic_launcher_background.xml`
  (delete the template's `drawable/ic_launcher_background.xml` and `drawable-v24/ic_launcher_foreground.xml`)

`git diff` shows the rest.
